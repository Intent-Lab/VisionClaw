# Jarvis OS 시스템 전반 테스트 브리프

## 1. 서비스 개요

Jarvis OS는 Meta Ray-Ban 스마트 글라스, Android 앱, Gemini Live, 로컬 FastAPI Memory Server를 연결한 개인 AI 비서 시스템입니다.

목표는 사용자가 스마트폰을 직접 조작하지 않고도 다음 일을 음성으로 처리하는 것입니다.

- 현재 보고 있는 장면에 대해 질문하기
- 현재 장면을 이미지와 함께 기억으로 저장하기
- 과거에 저장한 기억, 명함, 문서, 사람, 회의 내용을 검색하기
- 회의를 녹음하고 회의록으로 요약하기
- 저장된 사람/연락처를 찾아 전화 또는 문자 보내기
- 일정, 문서, 연락처 같은 개인 작업으로 확장하기

핵심 UX는 “글라스로 보고, 말로 요청하고, AI가 기억하거나 찾아주는 것”입니다.

## 3. 전체 동작 흐름

### 3.1 실시간 질문 흐름

1. 사용자가 AI 버튼을 누르거나 “자비스”라고 말합니다.
2. Android STT가 한국어 음성을 텍스트로 변환합니다.
3. Gemini가 사용자 요청을 해석합니다.
4. 현재 시야가 필요한 질문이면 `capture_current_view`를 호출합니다.
5. 앱이 최신 이미지를 캡처해서 Gemini 대화에 첨부합니다.
6. Gemini가 이미지와 질문을 기반으로 답변합니다.

### 3.2 기억 저장 흐름

1. 사용자가 “이거 저장해줘”라고 말합니다.
2. Gemini가 현재 시야 캡처를 요청합니다.
3. 앱이 이미지를 캡처합니다.
4. Gemini가 장면을 설명하고 저장 확인을 받습니다.
5. 사용자가 승인하면 `save_life_memory`를 호출합니다.
6. 서버가 이미지, 사용자 메모, AI 해석, 라벨, 객체, 시간 정보를 저장합니다.
7. 저장 텍스트가 임베딩되어 벡터 검색 대상이 됩니다.

### 3.3 기억 검색 흐름

1. 사용자가 과거 기억을 질문합니다.
2. Gemini가 `universal_search`를 호출합니다.
3. 서버가 memories 벡터 검색과 정확 검색을 함께 수행합니다.
4. 관련 people, person_candidates, meeting, entities, needs를 함께 반환합니다.
5. Gemini가 검색 결과를 자연어로 요약합니다.

### 3.4 회의 기록 흐름

1. 사용자가 “회의 시작” 또는 “이 회의 기록해줘”라고 말합니다.
2. 앱 로컬 음성 명령이 회의 녹음을 시작합니다.
3. 회의 중 발언은 AI 명령으로 처리하지 않습니다.
4. 사용자가 “회의 녹음 종료”라고 말하거나 앱 버튼으로 종료합니다.
5. 서버가 녹음 파일을 STT로 변환합니다.
6. 서버가 회의 요약, 회의록, 액션 아이템을 생성합니다.
7. 앱 회의 목록에서 상세 내용을 확인하고 공유할 수 있습니다.

### 3.5 전화/문자 흐름

1. 사용자가 “OO에게 전화해줘” 또는 “OO에게 문자 보내줘”라고 말합니다.
2. Gemini가 먼저 `universal_search`로 Jarvis DB의 사람 후보를 찾습니다.
3. 후보가 없거나 사용자가 연락처 검색을 원하면 `search_contacts`로 Android 전화번호부 후보를 찾습니다.
4. 후보가 여러 명이면 번호로 선택하게 합니다.
5. 사용자가 대상을 확정한 뒤 `call_contact` 또는 `text_contact`를 실행합니다.

## 4. 구현된 주요 기능

### 4.1 글라스/폰 카메라 기반 시야 인식

테스트 문장:

```text
자비스, 지금 보고 있는 물건이 뭐야?
자비스, 이 문서 내용 읽어줘
자비스, 이 명함 누구 거야?
```

합격 기준:

- 현재 시야가 필요한 질문에서 이미지 캡처가 발생해야 합니다.
- 이미지 없이 추측으로만 답하면 실패입니다.
- 답변은 “확실하지 않다”는 표현을 포함할 수 있어야 하며, 없는 정보를 단정하면 실패입니다.

### 4.2 일상 기억 저장

테스트 문장:

```text
자비스, 이거 저장해줘
지금 보는 거 기억해줘
이 명함 저장해줘
```

합격 기준:

- 바로 저장하지 않고 현재 장면을 설명해야 합니다.
- 저장 확인 질문을 해야 합니다.
- 승인 후 DB에 저장되어야 합니다.
- 저장된 기억은 이후 검색 가능해야 합니다.

### 4.3 기억 검색

테스트 문장:

```text
아까 저장한 명함 찾아줘
어제 본 문서 뭐였지?
지난번 저장한 빨간 자동차 찾아줘
```

합격 기준:

- `universal_search` 기반 검색이 동작해야 합니다.
- 유사도 높은 기억을 우선 반환해야 합니다.
- 이미지, AI 해석, 사용자 메모가 상세 화면에서 확인 가능해야 합니다.

### 4.4 사람/연락처 검색

테스트 문장:

```text
유나 찾아줘
유나한테 전화해줘
김윤섭한테 문자 보내줘
```

합격 기준:

- Jarvis DB 후보와 Android 연락처 후보를 모두 고려해야 합니다.
- 연락처에 같은 이름이 여러 명 있으면 후보를 번호로 보여줘야 합니다.
- 후보가 여러 명인데 바로 전화/문자를 실행하면 실패입니다.

### 4.5 전화 걸기

테스트 문장:

```text
유나한테 전화해줘
김윤섭에게 전화 걸어줘
```

합격 기준:

- 후보 확인 후 전화가 실행되어야 합니다.
- Android 연락처 권한이 없으면 명확한 권한 오류를 알려야 합니다.

### 4.6 문자 보내기

테스트 문장:

```text
유나한테 지금 출발한다고 문자 보내줘
오늘 회의한 거 김윤섭에게 문자로 보내줘
```

합격 기준:

- 수신자 후보를 먼저 확인해야 합니다.
- 회의 내용을 문자로 보낼 때는 회의 검색 후 요약 문장을 만들어야 합니다.
- 수신자가 확정된 뒤에만 SMS를 보내야 합니다.

### 4.7 회의 녹음/요약

테스트 문장:

```text
회의 시작
회의 녹음 종료
```

합격 기준:

- 회의 시작 안내가 나와야 합니다.
- 회의 중 일반 발화가 AI 명령으로 처리되지 않아야 합니다.
- 종료 후 회의록이 생성되어야 합니다.
- 회의 목록에서 상세 내용과 공유 기능이 보여야 합니다.

### 4.8 STT 발화 끊김

테스트 문장:

```text
내가 있잖아... 유나한테 전화하려고 하는데 찾아줘
```

합격 기준:

- `내가 있잖아`만 먼저 요청으로 보내지 않아야 합니다.
- 짧은 침묵 후 이어진 발화를 합쳐서 처리해야 합니다.
- 너무 오래 기다려 응답성이 심하게 떨어져도 실패입니다.

### 4.9 기억/회의 UI

테스트 항목:

- 기억 목록
- 기억 상세
- 회의 목록
- 회의 상세
- 회의 공유
- 뒤로가기
- 글라스 스트림 유지

합격 기준:

- 목록 진입 후 뒤로가기가 앱 홈으로 튕기면 실패입니다.
- 글라스 연결이 끊기면 실패입니다.
- 상세 화면에서 요약/원문/이미지 정보가 읽기 쉬워야 합니다.

## 5. E2E 테스트 시나리오

### 시나리오 A. 현재 물체 질문 후 저장

1. 글라스 또는 폰 카메라를 물체에 향합니다.
2. 말합니다.

```text
자비스, 지금 보고 있는 물건이 뭐야?
```

3. 답변을 확인합니다.
4. 이어서 말합니다.

```text
이거 저장해줘
```

5. AI가 저장 확인 질문을 하는지 확인합니다.
6. 말합니다.

```text
응 저장해
```

7. 기억 목록에서 저장된 항목과 이미지를 확인합니다.

### 시나리오 B. 명함 저장 후 검색

1. 명함을 카메라 앞에 둡니다.
2. 말합니다.

```text
자비스, 이 명함 저장해줘
```

3. AI가 이름/회사/연락처를 가능한 범위에서 해석하는지 확인합니다.
4. 저장 승인합니다.
5. 말합니다.

```text
방금 저장한 명함 찾아줘
```

6. 검색 결과가 저장한 명함과 연결되는지 확인합니다.

### 시나리오 C. 회의 기록 후 문자 공유

1. 말합니다.

```text
회의 시작
```

2. 20~30초 동안 회의 내용을 말합니다.
3. 말합니다.

```text
회의 녹음 종료
```

4. 회의 목록에서 회의록이 생성되었는지 확인합니다.
5. 말합니다.

```text
오늘 회의한 거 유나한테 문자로 보내줘
```

6. 연락처 후보가 뜨는지 확인합니다.
7. 후보 선택 후 문자 전송이 되는지 확인합니다.

### 시나리오 D. 연락처 동명이인 처리

1. Android 연락처에 같은 이름 또는 비슷한 이름 2명 이상이 있는 상태를 준비합니다.
2. 말합니다.

```text
유나한테 전화해줘
```

3. 후보가 2명 이상 표시되는지 확인합니다.
4. 말합니다.

```text
2번
```

5. 선택한 연락처로 전화가 실행되는지 확인합니다.

### 시나리오 E. 목록 진입 중 글라스 연결 유지

1. 글라스 스트림을 시작합니다.
2. 기억 목록으로 들어갑니다.
3. 회의 목록으로 이동합니다.
4. 상세 화면에 들어갔다가 뒤로 나옵니다.
5. 스트림 화면으로 돌아옵니다.

합격 기준:

- 글라스 연결이 유지되어야 합니다.
- 앱이 홈 화면으로 내려가면 실패입니다.
- 다시 AI 질문이 가능해야 합니다.

## 6. 실패로 봐야 하는 동작

- 연락처에 있는 사람을 바로 “없다”고 답함
- 후보가 여러 명인데 전화/문자를 바로 실행함
- 현재 시야 질문인데 이미지 캡처 없이 추측함
- 저장 요청에서 사용자 확인 없이 바로 저장함
- 회의 중 참석자 발화를 AI 명령으로 처리함
- 회의 종료 후 회의록이 생성되지 않음
- 기억/회의 목록 진입 후 글라스 연결이 끊김
- 짧은 쉼표마다 요청이 잘려 Gemini로 전송됨
- 서버 연결 실패를 사용자에게 설명하지 않음

## 7. 현재 알려진 제약

- Meta Ray-Ban 영상 스트림은 실제 시야보다 지연될 수 있습니다.
- 글라스 스트림 화질은 DAT SDK와 네트워크 상태의 영향을 받습니다.
- 이미지 인식은 모델이 오판할 수 있으므로 확실하지 않은 내용은 단정하면 안 됩니다.
- 짧은 고유명사 STT는 완벽하지 않으므로 후보 선택 UX가 중요합니다.
- Cloudflare Tunnel 주소는 임시 주소라 끊기면 앱 설정의 서버 URL을 새 주소로 바꿔야 합니다.
- Whisper.cpp는 비교용으로 남아 있고 기본 STT는 Android ko-KR입니다.
