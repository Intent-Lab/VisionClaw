# 실시간 음성 대화

설정 → 음성 대화 → **실시간 대화**가 기본으로 켜집니다. AI 버튼 또는 호출어로 시작하고 종료 버튼으로 끝냅니다. 활성 세션에서는 호출어를 반복하지 않아도 후속 대화가 이어집니다. 끄면 기존 Android/Whisper STT 경로를 사용할 수 있습니다.

## 동작

- 마이크의 16kHz mono PCM16을 40ms 단위로 Gemini Live에 전송합니다. 별도 STT의 최종 문장이나 앱의 1.5초 합치기 타이머를 거치지 않습니다.
- 서버 VAD의 무음 대기는 700ms로 시작합니다. 이 값은 응답 시간 보장이 아니며 네트워크, 서버 추론, 오디오 장치 지연이 추가됩니다.
- 재생과 캡처가 동시에 진행됩니다. 지원되는 기기에서 에코 제거와 잡음 억제를 활성화합니다.
- `interrupted`를 받으면 앱의 PCM 큐와 AudioTrack 버퍼를 함께 비웁니다. 소켓 수신 스레드는 오디오 재생 완료를 기다리지 않습니다.
- 전화/문자 승인 및 회의 녹음 명령은 실시간 모드에서 도구 호출로 처리합니다. 자막 조각을 명령으로 실행하지 않습니다. 전화/문자는 대기 중인 요청 ID가 일치해야 승인할 수 있습니다.
- 기존 연락처 힌트와 한국어 문맥을 유지합니다. 정확도 개선은 기기 테스트로 검증해야 합니다.

## 기기 확인 항목

1. AI 버튼으로 연결하고 한국어 질문을 세 번 이어서 말합니다. 답변 후 세션이 유지되는지 확인합니다.
2. 호출어로 시작한 뒤 후속 질문에서 호출어를 생략합니다.
3. 긴 답변 중 "잠깐, 그거 말고…"라고 말합니다. 이전 음성이 멈추고 대기 음성이 다시 재생되지 않는지 확인합니다.
4. 문장 중간에 300~500ms 쉬고 이어 말합니다. 짧은 쉼이 불필요한 답변을 유발하는지 확인합니다.
5. 스피커와 블루투스 장치를 각각 시험합니다. AI의 목소리를 사용자 발화로 인식하거나 스스로 끊지 않는지 확인합니다.
6. 연락처 후보 선택 → 실행 확인 → 취소 흐름을 확인합니다. 승인 없이 실행되지 않아야 합니다. 실제 전화/문자는 명시적으로 승인한 테스트 수신자로만 시험합니다.
7. "회의 녹음 시작하지 마"는 녹음을 시작하지 않아야 합니다. 명시적인 시작 요청에는 대화가 종료되고 회의 녹음 화면으로 전환되어야 합니다.
8. 연결 중/재생 중 종료, 네트워크 재연결을 시험합니다. 마이크가 해제되고 이전 답변이 새 세션에 섞이지 않아야 합니다.
9. 실시간 대화를 끄고 기존 STT 경로에서 답변 끝까지 재생되는지 확인합니다.

동일한 한국어 발화 세트로 이름·숫자 정확도, 문장 잘림, 마지막 음절부터 첫 응답 음성까지의 p50/p95, 끼어들기 중단 시간을 비교합니다. 기존 `[Latency]` 로그는 마지막 입력 자막 수신부터 첫 응답 오디오 수신까지이며 실제 음향 지연 측정과 다릅니다.

자동 테스트: `./gradlew :app:testDebugUnitTest` (부분 쓰기, 출력 혼잡, 끼어들기 큐 삭제, 메모리 상한, 재생 오류 처리).

참고: [Gemini Live VAD 및 interruption](https://ai.google.dev/gemini-api/docs/live-api/capabilities), [Android 에코 제거](https://developer.android.com/reference/android/media/audiofx/AcousticEchoCanceler).
